# 照合のテスト

照合ルール（`check_csv.py`）を直したら、**テスト.bat** をダブルクリックして全部 `ok` になるか確認します。
最後に `OK` と出れば、今までの事例はすべて前と同じに判定されています。`FAILED` なら、どの事例が変わったかが表示されます。

| ファイル | 中身 |
|---|---|
| `test_matching.py` | 事例表（下記）のとおりに判定されるか。価格変更なら「REINSの新価格」をサイトに入れるかも確認 |
| `test_rules.py` | 表記ゆれ・価格・面積・階・駅・会社名の判定部品 |
| `test_db_check.py` | REINS物件DBの読み込み時チェック（列や状態がおかしければ止まる） |

`expected failure` と出るのは「既知の問題」として記録してあるテストです（直すまではこの表示で正常）。

## 事例の足し方

照合を間違えた物件が見つかったら、その物件を事例として足しておくと、直したあとに二度と同じ間違いをしなくなります。

事例は2つのCSVに書き、**事例ID** で組にします。Excelで開いて編集できます。

- `自社CSV.csv` … 自社の物件一覧CSV（ハウスフリード）の1行
  - 先頭に `事例ID` / `期待結果` / `期待する物件番号`（省略可）/ `メモ` を書く
  - 期待結果は `一致` / `価格変更` / `成約確定` / `成約候補` のどれか
- `REINS.csv` … 照合相手になるREINS物件DBの行（何行でも）
  - 先頭に `事例ID` / `区分`（`物件DB` か `成約・取消`）を書く
  - `成約・取消日` は `3日前` のように書くと、いつテストしても同じ結果になる

### 置き場所

| フォルダ | 使い分け |
|---|---|
| `tests/cases/` | 架空の住所・会社名で作った事例。GitHubに上がる |
| `tests/cases_local/` | 実際の物件の行をコピーして作った事例。**GitHubに上がらない**（`.gitignore`） |

リポジトリは公開なので、実際の物件（REINSのデータ）は必ず `cases_local/` に入れてください。
`cases_local/` は `cases/` と同じ形（`自社CSV.csv` と `REINS.csv`）で作れば、テスト.bat が両方を読みます。
